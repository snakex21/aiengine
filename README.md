# AIEngine

> *Models, textures, and game logic generated by LLMs.*

**AIEngine** is a Doom-style 2.5D game engine built from scratch in Go.
It uses DDA raycasting with a CPU pixel-buffer, embeds Lua and JavaScript VMs,
and introduces its own `.aie` format for AI-generated game content.

## Quick Start

```bash
git clone https://github.com/snakex21/aiengine.git
cd aiengine
go mod tidy
go build -o bin/aiengine.exe .
./bin/aiengine.exe
```

Or build both engine and editor on Windows:

```powershell
./scripts/build.ps1 -RunTests
```

**Requirements:** Go 1.26+, OpenGL 3.3+, Windows 10/11 64-bit.

### Project layout

Game projects live in `projects/<name>/`, so every project can keep its own
maps, scripts, styles, config, and assets:

```text
projects/demo/
├─ config.aie
├─ manifest.aie
├─ assets/
├─ entities/
├─ maps/
├─ scripts/
└─ styles/
```

By default the engine runs `projects/demo`. To run another project:

```bash
AIENGINE_PROJECT=projects/my-game ./bin/aiengine.exe
```

You can also pass a project explicitly:

```bash
./bin/aiengine.exe --project my-game
./bin/aiengine.exe --project projects/my-game
```

If multiple projects exist and no project is provided, `aiengine.exe` lists
available projects in the console and asks which one to run.

### Native editor

The lightweight editor is now a Go + WebView2 desktop app. It does **not** use
Tauri, Vite, Electron, or a localhost dev server.

```bash
go build -ldflags "-H=windowsgui" -o bin/AIEngine-Editor.exe ./cmd/editor
./bin/AIEngine-Editor.exe
```

For console logs while developing, omit `-ldflags "-H=windowsgui"`:

```bash
go run ./cmd/editor
```

On Windows it uses Microsoft Edge WebView2 Runtime, which is usually already
installed on Windows 10/11.

## What makes it different

- **AI-first design** — `.aie` format designed for LLM content generation
- **CPU pixel-buffer renderer** — no GPU driver issues, works everywhere
- **Dual scripting** — Lua for game logic, JavaScript for UI/HUD
- **CSS for games** — colors, textures, effects via familiar CSS syntax
- **Procedural audio** — describe sounds in `.aie`, engine generates them
- **Single .exe** — zero external runtimes, Lua and JS VMs embedded

## Architecture

```
Go Core
├── GLFW          Native window
├── OpenGL 3.3    DDA Raycaster
├── gopher-lua    Lua VM
├── goja          JS VM
└── Custom Parser .aie / .css / config
```

| Language | Role |
|----------|------|
| Go | Engine, renderer, physics, parser |
| Lua | Mission logic, enemy AI, events |
| JS | UI, HUD, menus, effects |
| CSS | Colors, textures, screen post-processing |

## Key Features

- ✅ DDA raycasting with textured walls & Z-buffer
- ✅ Billboard sprites with angular positioning
- ✅ Predictive per-axis collision (wall sliding)
- ✅ Perlin noise procedural textures (brick, stone, metal, wood, skin)
- ✅ Procedural sound generation (6 waveforms, ADSR envelope)
- ✅ Lua scripting with 45+ API functions
- ✅ JS scripting with 50+ API functions (UI, HUD, menus)
- ✅ Per-part HP system with phases, weak spots, armor
- ✅ 8 weapon types with hitscan, spread, reload
- ✅ Trigger system (9 conditions, 15 actions)
- ✅ Cutscene system (4 complexity levels)
- ✅ Ragdoll physics (Verlet chain)
- ✅ UDP multiplayer protocol (server + client)
